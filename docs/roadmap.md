# 开发任务与阶段验收

更新：**2026-10-03 / v0.3**。当前学习重点是模型训练之外的数据工程：来源、清洗、时间对齐、样本与预处理。本次补充计划，不表示已经实现这些能力；实际模型训练仍为下一阶段。任务状态按验收条件判定，部分完成不等同关闭。

## 当前执行主线：先交付可信的训练样本

假设已经掌握机器学习基本原理，每个任务同时产出工程结果和一份解释设计取舍的记录。状态以本文件为准；日常步骤、任务拆分和模板见[开发流程](development-workflow.md)。

```text
L01 定义任务与字段
  → L02 保存来源 → L03 真实核验 → L04 质量规则
  → L05 因果时间对齐 → L06 固定比赛划分
  → L07 历史特征 + L08 未来标签
  → L09 仅训练集拟合预处理 → L10 固定派生样本
  → L11 泄漏与样本审计 + L12 恢复演练
  → 后续 ML02–ML04：基线、模型、独立评估与复盘
```

L05 的确定性规则不从数据拟合参数；真实派生样本和任何统计拟合必须在 L06 固定划分后生成。L12 可以在数据准备期间推进，不需要先训练模型。没有真实样本时可以用 synthetic 实现接口和负例，但 L03 的真实验收及后续真实数据资格不能勾选。

L 编号是学习与交付切片，D/V/E/ML 是长期能力清单。完成 L 任务只更新原任务实际满足的子项，不能自动关闭整条原任务。例如 L01 只确定首个任务，不代表 ML01 的样本和标签实现已完成。

## 建议的迭代顺序与出口

| 迭代 | 范围 | 最小可演示成果 | 进入下一阶段的条件 |
|---|---|---|---|
| I1：问题与证据 | L01–L03 | 一条真实购买记录从回放到规范 JSON 的追溯，附字段与核验记录 | 目标字段已核验，未知字段排除或形成明确阻塞；样本范围已记录 |
| I2：清洗与划分 | L04–L06 | 一份逐场质量报告、一份持久化排除清单、一个固定比赛快照 | 阈值及缺失策略有来源；独立比赛数清楚；测试集身份固定 |
| I3：样本与预处理 | L07–L10 | 一个指定时刻的 X/y、证据和可加载的预处理产物 | cutoff、标签观察范围与 train-only 拟合通过；派生样本版本可追踪 |
| I4：审计与恢复 | L11–L12 | 一份样本审计报告和一次备份恢复演示 | 防泄漏、边界、错误记录及恢复验收通过，剩余限制明确 |

不按固定周数承诺进度；每轮可以拆成多个小 PR。原始数据缺失、语义无法确认或兼容性不明时，在任务记录中写明阻塞与下一步，而不是跳过验收。CPU/合成数据足够支持接口开发；Parquet、GPU、Web 上传与队列不作为本阶段前置条件。

## 任务完成规则

每项关闭需要具体改动、正反例结果、数据/Schema 兼容说明和文档更新。保留旧编号便于追踪，不为“已有部分实现”虚报完成。每次只选择可独立验收的改进，验证相关风险后继续交付，不以测试数量代替真实数据质量。
