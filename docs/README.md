## 文档权威边界

- **当前行为**以源码、已运行检查和工程设计的“已实现”部分为准。
- **未来约定**以数据契约为字段/状态依据，以长期路线为模块边界依据，以交付规范为验收依据。
- **任务是否完成**只看 roadmap 的状态及关联证据，不能因某项写入设计而打勾。
- **历史发现**保留审查时的版本和日期；修复后在 roadmap 记录提交，不把历史审查改写成新事实。
- 设计冲突先更新对应权威文档，再改依赖它的任务；不在代码与多份文档中各自猜测。

## 近期重点与长远目标

近期先完成 D01 证据链校验，再完成去重、缓存与重跑恢复；人工选择英雄和比赛可并行进行。

具体英雄、位置、候选装备、机器资源和每周投入尚未确定。设计采用可配置范围，
不预设用户擅长英雄，不承诺按固定日期交付，也不以增加技术栈数量衡量项目价值。
